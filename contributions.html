NASA F Prime: FileHandling Subtopology Framework Dependency Resolution

In NASA Jet Propulsion Laboratory F Prime flight software, subtopology configurations define core infrastructure constants for mission flight deployments. Following architectural refactoring to compile string constants in FppConstantsAc.cpp, FileHandlingConfig lacked an explicit dependency on the Fw_Types target. This triggered downstream build failures due to missing framework include paths during target compilation. The contribution added the explicit Fw_Types dependency to register_fprime_config, aligning FileHandling with sibling configurations and ensuring clean compilation across deep-space flight project deployments.

Target Repository: nasa/fprime (devel / main release tree)
Upstream Reviewer: Michael Starch (LeStarch, NASA JPL F Prime Lead Architect)
Status: Merged into NASA F Prime release tree
Technical Surface: Resolved build system dependency graph in Svc/Subtopologies/FileHandling/FileHandlingConfig/CMakeLists.txt, restoring Fw_Types include paths for downstream space flight projects.

NASA F Prime: CCSDS CFDP Metadata PDU Closure Flag Specification Fix

F Prime is NASA Jet Propulsion Laboratory open-source flight software framework used across CubeSats, planetary landers, and robotic exploration missions. In the CCSDS File Delivery Protocol (CFDP) manager component, the closure requested flag in Metadata PDUs was incorrectly mapped against bitmask 0x04 instead of bit 0x40 as mandated by the CCSDS 727.0-B-4 blue book specification. This mismatch caused flight file uplink sessions requesting explicit transaction closure to mishandle final acknowledgement state machines. The fix corrected the bitmask constant and resolved transaction stalls across deep-space telemetry pipelines.

Target Repository: nasa/fprime (master branch)
Upstream Reviewer: Thomas Baudequin (thomas-bc, NASA JPL core team)
Status: Merged into NASA F Prime release tree
Technical Surface: Corrected Svc/Ccsds/CfdpManager Metadata PDU parsing logic to conform with CCSDS 727.0-B-4 standards, ensuring robust transactional closure detection on mission communications busses.

Microsoft VS Code: Portable Environment Isolation and Case-Insensitive CLI Quality Parsing

Visual Studio Code is the industry-standard developer environment deployed across millions of workstations. During invocation through headless automation and containerized development workflows, the core CLI runtime failed to consistently respect the VSCODE_PORTABLE environment variable when resolving local storage roots. Furthermore, strict case sensitivity during release quality channel parsing triggered silent fallback faults when input parameters were formatted in mixed casing. The patch enforced strict environment hierarchy validation and normalized release quality tokens across all supported operating systems.

Target Repository: microsoft/vscode (main branch)
Upstream Reviewer: Connor Peet (connor4312, Microsoft VS Code Core maintainer)
Status: Merged into Microsoft VS Code main branch
Technical Surface: Refactored CLI environment inspection routines to prioritize portable data roots and implemented normalized string comparison for release quality channels.

Linux Kernel Sched-ext: scx_intent 5-Tier Intent-Driven CPU Scheduling

Standard desktop and server Linux workloads frequently encounter micro-stuttering and latency spikes when background compute processes compete for execution slots with interactive window compositors and real-time audio threads. Exploidus authored scx_intent as a native in-kernel eBPF scheduler and contributed it upstream to the Linux sched-ext framework to deliver deterministic priority isolation without complex cgroup management overhead.

Target Repository: sched-ext/scx (Linux 6.12+ extensible scheduler architecture)
Status: Upstream RFC submitted under Pull Request #3845
Technical Surface: Configured 5 isolated Dispatch Queues handling Audit, Interactive, IO, Network, and Compute tiers. Resolved multi-core SMP starvation races by adopting per-CPU accounting structures, added immediate preemption dispatch via SCX_KICK_PREEMPT, and enforced strict bounds checking on dynamic BPF intent maps.
